# DLS-0001 — DevHub Language Standard

**Документ:** DLS-0001  
**Название:** Стандарт языка интерфейса DevHub  
**Статус:** Approved  
**Версия:** 1.0  
**Продукт:** DevHub  

---

## 1. Назначение

DevHub Language Standard определяет правила языка, терминологии и формулировок пользовательского интерфейса DevHub.

Цель стандарта — обеспечить единый, понятный и профессиональный язык продукта.

---

## 2. Основное правило

Пользовательский интерфейс DevHub по умолчанию отображается на русском языке.

Внутренний код, имена классов, функций, модулей и технических сущностей могут использовать английский язык.

---

## 3. Брендовые термины

Следующие названия не переводятся:

- DevHub
- DevAdvisor
- DevScore
- DHMS
- DPS
- DEM

Эти термины являются частью продуктового языка и бренда DevHub.

## 5. Статусы синхронизации

| Внутренний статус | Текст в интерфейсе |
|---|---|
| SYNCED | Синхронизировано |
| PULL_REQUIRED | Есть изменения на GitHub |
| PUSH_REQUIRED | Есть локальные изменения |
| COMMIT_REQUIRED | Требуется Commit |
| ERROR | Ошибка |
| UNKNOWN | Неизвестно |

---

## 6. Правила сообщений

Сообщения должны быть:

- понятными;
- краткими;
- инженерно точными;
- без лишней эмоциональности;
- с указанием рекомендуемого действия.

Плохо:

```text
Ошибка.
```

Хорошо:

```text
Не удалось получить изменения из GitHub. Проверьте подключение к интернету и настройки SSH.
```

---

## 7. Правила подсказок

Каждая важная кнопка должна иметь всплывающую подсказку.

Пример:

```text
Получить изменения
Загружает изменения из GitHub в локальный репозиторий.
```

Пример:

```text
Отправить изменения
Отправляет ваши локальные Commit на GitHub.
```

---

## 8. DevAdvisor

Название DevAdvisor не переводится.

Текст рекомендаций DevAdvisor должен быть на русском языке.

Каждая рекомендация должна содержать:

1. Что обнаружено.
2. Почему это важно.
3. Что рекомендуется сделать.

Пример:

```text
README отсутствует или пустой.

Это затрудняет понимание назначения проекта и его структуры.

Рекомендуется создать README с описанием проекта, структуры, установки и запуска.
```

---

## 9. Принцип

DevHub должен быть понятен пользователю, который не обязан знать команды Git.

Поэтому вместо технических команд используются смысловые действия:

- Проверить изменения;
- Получить изменения;
- Отправить изменения;
- Анализ проекта;
- Синхронизировать все.
