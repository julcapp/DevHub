# ADR-001. Единая модель инженерных объектов

- **Статус:** Принято
- **Дата:** 2026-07-23
- **Контекст:** DevHub v0.4 Alpha

## Решение

Все значимые сущности DevHub представляются как `Engineering Object` (EO) с единым набором системных атрибутов и жизненным циклом.

Repository является источником кода. Project представляет продукт. Artifact является единицей инженерного знания. Все они реализуются как специализированные Engineering Objects.

## Обязательные атрибуты EO

- `id` — стабильный идентификатор вида `EO-<TYPE>-<NUMBER>`;
- `type` — тип объекта;
- `title` и `description`;
- `status`;
- `author_id`;
- `source_type` и `source_ref`;
- `created_at`, `updated_at`;
- `version`;
- `ai_summary`;
- `metadata`;
- журнал событий и история изменений.

## Базовые типы

- `PROJECT` — проект или продукт;
- `REPOSITORY` — локальный или удалённый репозиторий;
- `STAR` — репозиторий из GitHub Stars;
- `IDEA` — инженерная или продуктовая идея;
- `RESEARCH` — исследование технологии или решения;
- `TECH` — технология;
- `ADR` — архитектурное решение;
- `DOC` — документ;
- `ARTIFACT` — иной инженерный артефакт.

## Последствия

1. Объекты сохраняют идентичность независимо от папки, Git URL или локального пути.
2. API, база данных, поиск и интерфейс используют единые идентификаторы.
3. Появляется трассируемость от идеи и внешнего источника до коммерческого продукта.
4. Новые типы объектов добавляются без изменения базового жизненного цикла.

## Ограничение контуров

DevHub и Lk_uni являются самостоятельными продуктами. DevHub не включает Lk_uni в свою архитектуру. Возможная интеграция допускается только через явно определённые API-контракты.
