# ADR-002. Граф связей инженерных объектов

- **Статус:** Принято
- **Дата:** 2026-07-23
- **Зависит от:** ADR-001

## Контекст

Реальные инженерные знания не укладываются в дерево папок: одна идея может быть связана с несколькими исследованиями, репозиториями, технологиями, ADR и продуктами.

## Решение

DevHub строит смысловой граф поверх файловой системы и Git. Узлами графа являются Engineering Objects, рёбрами — типизированные связи.

## Базовые связи

- `DERIVED_FROM` — объект создан на основе другого объекта;
- `RESEARCHES` — исследование изучает источник;
- `IMPLEMENTS` — проект или репозиторий реализует идею/ADR;
- `USES` — объект использует технологию или компонент;
- `RELATED_TO` — смысловая связь общего назначения;
- `SUPERSEDES` — новая версия заменяет предшественника;
- `PRODUCES` — исследование или идея порождает проект/артефакт;
- `DOCUMENTS` — документ описывает объект;
- `FORK_OF` — репозиторий является GitHub Fork;
- `EVOLVES_INTO` — этап эволюции переходит в следующий.

## Правила

1. Каждая связь имеет собственный ID, автора, дату создания, источник и необязательное обоснование.
2. Направление связи хранится явно.
3. Удаление узла не должно молча уничтожать историю происхождения.
4. Файловая система остаётся способом хранения кода и документов, но не является моделью знаний.

## Основные режимы интерфейса

- Workspace — проекты и повседневная работа;
- Knowledge — знания, документы и технологии;
- Research — идеи, GitHub Stars и исследования;
- Evolution — происхождение и развитие продуктов.
