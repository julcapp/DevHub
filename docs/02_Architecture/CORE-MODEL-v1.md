# DevHub Core Model v1

## 1. EngineeringObject

Базовая сущность всех инженерных объектов.

```text
EngineeringObject
- id
- type
- title
- description
- status
- author_id
- source_type
- source_ref
- version
- ai_summary
- metadata
- created_at
- updated_at
```

## 2. Основные сущности

### Project

Продукт или самостоятельная разработка. Может иметь несколько репозиториев, идей, исследований, ADR и релизов.

### Repository

Источник кода. Хранит GitHub URL, локальный путь, ветки, origin/upstream, лицензию и состояние синхронизации.

### Star

Карточка GitHub Star, импортированная в DevHub. Это не внутренний рейтинг и не декоративная отметка.

Дополнительные поля:

- GitHub repository ID и URL;
- владелец и название;
- README summary;
- стек технологий;
- лицензия;
- активность и дата последнего обновления;
- GitHub stars/forks/issues;
- Evolution Score;
- совместимость с проектами;
- статус исследования;
- принятое решение;
- пользовательские заметки.

### Idea

Инженерная или продуктовая идея с авторством, временной меткой, материалами подтверждения, приоритетом и связанными объектами.

### Research

Управляемое исследование внешнего проекта или технологии. Содержит цель, гипотезы, результаты анализа, риски, вывод и рекомендуемое действие.

### Technology

Элемент каталога технологий: назначение, версии, преимущества, ограничения, совместимость и фактическое использование.

### Artifact

Единица инженерного знания: документ, диаграмма, макет, API-спецификация, SQL-схема, конфигурация, отчёт или иной материал.

### EvolutionNode

Этап происхождения и развития продукта: внешний репозиторий, Star, исследование, решение, Fork, производный проект, самостоятельный продукт.

## 3. Жизненный цикл Star

```text
GitHub Star
→ импорт метаданных
→ AI-анализ
→ классификация
→ оценка рисков и лицензии
→ рекомендация действия
→ исследование
→ архитектурное решение
→ Fork/Clone или использование как зависимости
→ производный проект
→ самостоятельная эволюция
```

## 4. Предлагаемые действия для Star

- изучить подробнее;
- создать исследование;
- клонировать локально;
- создать GitHub Fork;
- начать собственную разработку;
- создать производный проект;
- использовать как библиотеку;
- связать с идеей, проектом или технологией;
- отложить;
- отклонить с фиксацией причины.

## 5. Мастер производного проекта

Мастер должен поддерживать:

1. проверку лицензии и ограничений;
2. выбор сценария: Fork, Clone, новый независимый репозиторий;
3. настройку `origin` и `upstream`;
4. создание рабочей ветки;
5. создание паспорта `.devhub/project.json`;
6. перенос AI-анализа и результатов исследования;
7. создание ADR происхождения;
8. создание ROADMAP, CHANGELOG и базовой документации;
9. регистрацию связи `DERIVED_FROM`/`FORK_OF`;
10. добавление проекта в Evolution Tree.

## 6. Принципы безопасности

- DevHub не выполняет Fork, Clone, Push или создание репозитория без явного подтверждения пользователя.
- Перед производной разработкой фиксируется лицензия исходника.
- Нельзя автоматически удалять сведения об исходном авторе и происхождении.
- Отделение от upstream оформляется как осознанное архитектурное решение.

## 7. Этапы реализации

### Этап A — модель и хранение

EngineeringObject, связи, Star, Idea, Research, Project и EvolutionNode.

### Этап B — GitHub Stars

Импорт, синхронизация, карточки, фильтры и пользовательские заметки.

### Этап C — AI Analysis

Резюме, стек, лицензия, активность, риски, совместимость и Evolution Score.

### Этап D — Research Workspace

Исследования, решения, связь с идеями и ADR.

### Этап E — Create Evolution Wizard

Fork/Clone, ветки, паспорт проекта, upstream и дерево происхождения.
